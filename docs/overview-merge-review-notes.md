# Overview merge — review notes

## Feature 02

- `src/outfits.jsx:157-168` (`OutfitPicker` hidden pieces) — retired pieces of an outfit are invisible in the picker yet silently re-appended on every save, so the user cannot remove them from the lineup and nothing in the UI says they are there. This preserves the modeled photo on a rename (good), but it is a product decision the spec doesn't cover. Suggested direction: show retired pieces as read-only, removable chips in the footer (or a "1 retired piece kept" note), or decide explicitly that they're permanent until the piece is restored.
- `src/outfits.jsx:157-168` + `shared/piece-selection.mjs:21-22` — a stored variantId that no longer exists is swapped for the default variant, so a rename-only save changes the lineup key and the server wipes the modeled photo, description and tags without any warning (`hasChanges` is false). Also a legacy `itemIds`-only outfit with a retired piece sends `variantId: null` and the save fails with a server validation error. Suggested direction: split name-only edits from lineup edits (PATCH `{ name }` alone when the visible selection is unchanged), which avoids both wipes.
- `src/components/PiecePicker.jsx:184-195` — Escape is captured on `window` in the capture phase with `stopImmediatePropagation`, so while the picker is mounted no other handler sees Escape (including native search-field clearing and any future layer above the picker such as toasts/menus). Acceptable now, but feature 03 stacks the picker on the cheat editor; suggested direction: a small shared Escape stack (topmost layer handles it) instead of per-component capture listeners.
- `src/components/PiecePicker.jsx` (no cap) vs `scripts/outfits-api.mjs` `pieces.slice(0, 12)` — a 13th piece is dropped silently server-side, and since hidden pieces are appended last they are cut first, changing the lineup. Suggested direction: expose a `maxPieces` prop (12 for outfits) that disables unselected cards with an explanatory title.

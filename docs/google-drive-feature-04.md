## Activation and safe controller contract

Add a server-only controller, exposed through the Google Drive plugin for feature 05. Same-origin, bounded JSON POSTs provide activation preview, explicit choice/cancel, manual restore preview/confirmation, and disable. A passive status route includes safe maintenance/progress/error state and archive generation; GET never enables or publishes. OAuth/configuration alone remains inactive.

The preview response exposes only opaque single-use action token, operation kind, concise decision, valid choices, semantic populated flags, file/byte counts, safe fingerprints, and curated remote error. Private staging paths, remote member IDs/maps, upload sessions, credentials, and raw exceptions remain server-only. Bind consent to the full target (`targetFingerprint`, `connectionGeneration`, `accountId`, `folderId`, `driveId`), local bytes and selected remote descriptor/inventory. Changed data or target rejects the confirmation; it never silently selects a newer backup. Preview TTL/cap and active-operation ownership are explicit; an accepted restore cannot lose its proof to preview expiry/GC.

| Local | Remote | Decision and authorized action |
| --- | --- | --- |
| Populated | Successfully verified empty | Require explicit `use-local`; activate and upload |
| Semantically empty | Complete valid populated archive | Offer explicit `use-drive`; restore every domain, then activate |
| Equivalent bytes | Equivalent bytes | `equivalent`; enable without content transfers |
| Different | Complete valid archive | `use-local`, `use-drive`, or cancel |
| Semantically empty | Successfully verified empty | `initialize`; enable a new archive |
| Any | Incomplete/invalid/unreadable | Curated error, no replacement/automatic activation |

Semantic emptiness counts all durable user domains/media. `library: []`, administrative generation/migration markers, default browser preferences and default AI mode do not themselves imply user content. A 403, failed page/read, corrupt inventory, or incomplete remote layout is never empty. Cancel leaves both copies intact and resumes a previously enabled worker only when its original target/fence still agrees. Disable drains outbound work, disables sync, and keeps both copies. Manual restore preserves the previously chosen storage mode; only activation's explicit `use-drive` flow enables Drive.

## Archive coordinator and writer admission

Introduce one reusable coordinator per resolved archive root, backed by restrictive private process-safe controls under `.google-drive`. Admission and maintenance acquisition must serialize across the backend and cooperating CLI/agent processes. A writer admitted before maintenance may complete; maintenance blocks new writers first and drains all admitted work before snapshot/download/swap. A dead process may release a lease only with checked ownership/liveness; malformed admission/maintenance records are preserved and reported. Avoid a race where a CLI joins between a drain observation and maintenance lock acquisition. Capture the archive generation at admission and reject stale prepared results at apply time.

Use scoped/nestable admission for HTTP mutation handlers, lazy GET/default/migration writers, and startup preparation. Register actual promises, not HTTP response lifetimes: import `running`/`runningModeled`; variants `running`/`runningPipelines`; outfits `running`; inspo `detecting`; wishlist `retrying`; cheat sheets `running`/`mutationQueue`, and any discovered asynchronous durable continuation. Background work must retain the originating lease through its final catalog/media write and follow-up preference signals. New background starts during maintenance fail safely before AI work. Existing read-only APIs remain readable only when they cannot expose mixed replacement state; return a curated retryable maintenance response when appropriate.

Integrate real non-HTTP writers: bulk prepare/apply, outfit regeneration, original-source capture, deterministic agent importer, and bundled import/outfit skill instructions. Store generation in prepared manifests/results and compare it at application. A stale external manifest cannot overwrite a restored archive. CLI invocation obeys the same process-safe maintenance protocol and startup recovery before migration/default writes. Protected `.agents` changes require the authorized sandbox escalation; never bypass it.

## Restore transaction and recovery

1. Pause and drain the outbound worker before acquiring the selected remote preview. Retain its previous mode/paused state for cancel/failure. Accept confirmation only against the exact selected evidence.
2. Acquire archive maintenance admission; block new mutations and await all backend background promises and CLI leases. Recheck local preview bytes and full target/source after drain. Local corruption may be repaired by restore: capture previous raw allowlisted domain bytes without requiring those old catalogs to pass schema validation.
3. Transfer/copy the confirmed remote source into journal-owned private staging using the bounded client and streamed path/size/SHA verification. Verify complete inventories, structural catalog schemas, portable media references and absence of secrets/control members. Re-read the selected descriptor/inventory as required; changed source is rejection. Do not follow arbitrary URLs or symlinks.
4. Produce a generation strictly greater than both old-local and selected-remote metadata/browser generation. Change `archive-metadata.json` only in generation; preserve all remote user payload bytes. Preserve browser payload, use the same new generation, revision at least remote revision, `migrationSealed: true`, and the full known migrated field list. Historical deleted-original limitations remain supported; references to removed garment/outfit IDs in legitimate history remain valid.
5. Persist an immutable transaction record and rollback capture before the first live rename. Journal/stages/backups live under stable `.google-drive`; move only explicit portable catalog/reference/media domains while leaving private auth/control in place. Replace the whole allowlisted archive, including removal of local members/catalogs absent remotely. Persist rename intent/completion and durable boundaries so every interrupted step can be resolved deterministically.
6. Invalidate the old sync epoch, operations, mappings and resumable sessions. Extend feature 03's restore authorization with durable, target/source-bound transaction ownership and active proof protection. Completion must validate the source/control-only transform; never bypass consent with missing evidence or an unconditional resume. Keep outbound work paused through the journal commit boundary. Manual completion restores prior mode; activation completion may enable.
7. On failure, undo every replacement domain and verify the recovered raw inventory/bytes against the previous capture even when the old archive was malformed. Keep journal evidence if rollback/recovery fails. Release maintenance only after one complete archive is proven. Never expose or resume a mixed archive.

Startup recovery runs in the earliest plugin configuration hook, before every archive preparation/default/migration writer, passive preview GC, or outbound start. Cooperating CLI entrypoints run recovery before their first archive write. Validate and preserve malformed/oversized journal/control records rather than resetting them. Recovery decides from durable journal phases and actual domain locations; it safely rolls back any incomplete transaction, or finalizes an already fully committed transaction. The tests inject failures/crashes before and after journal saves and every replacement/rollback rename. GC recognizes journal-owned stages and cannot sweep active recovery evidence.

## Structural validation and client invalidation

Strengthen shared `validateArchive` for publication and restore, not just JSON parse/hash correctness. Arrays/objects, required identity fields and durable preference/control shapes must match each supported catalog, while accepting known legacy record forms. Validate bounded archive-relative media paths and required referenced media. Correct checksums do not make a malformed library object or domain schema valid.

Expose archive maintenance/generation without AI setup dependency for feature 05. On observed generation change, invalidate every mounted app domain and derived state (wardrobe/outfit indexes, outfits, inspo, wishlist, cheat sheets, preferences, color profile, open viewers/jobs). Existing monotone browser-state focus/visibility refresh remains the cross-browser trigger; add any required refresh/poll integration for other connected browsers. Prevent late old-generation responses from repopulating stale state.

Year-long immutable library media caching requires a generation/version cache key for every archive media URL, including responsive IPX paths. A page reload alone does not invalidate same-path bytes. Make restored same-path images request the new key and ensure any image transformation cache is similarly keyed. During maintenance, disable/close mutation affordances only as necessary for existing UI correctness; the storage settings UI is deferred to 05.

## Implementation evidence and handoff

The implementation keeps the local archive authoritative and leaves settings UI to feature 05. The server-only `createGoogleDriveArchiveManager({ dataDir, service, worker })` factory uses the plugin's existing service and worker singleton: `preview("activation" | "restore")` returns an opaque single-use token and safe decision summary; `choose({ actionToken, choice, operation })` accepts only the preview's allowed choice; `status()` reports safe maintenance, operation progress/error, and archive generation. The plugin retains `getService()` and `getSyncWorker()`; the manager remains internal and has no plugin getter. Feature 05 uses `GET /api/google-drive/archive/status`, `POST /api/google-drive/archive/activation/preview`, `POST /api/google-drive/archive/restore/preview`, `POST /api/google-drive/archive/activation/choice`, `POST /api/google-drive/archive/restore/confirm`, and `POST /api/google-drive/archive/disable`. Mutating routes require the configured same-origin callback origin. Choice routes bind the operation kind to the route; `use-drive` returns a running operation ID, and status reports its stage/progress until completion. OAuth, verification, configuration, status reads, and GETs remain passive.

The archive coordinator is shared by Vite handlers, background continuations and CLI writers. `ensureArchiveRecovered(dataDir)` is an awaited barrier before defaults, migrations, preview cleanup, or writer admission; `withArchiveWriteLease(dataDir, task)` holds a process-safe lease around the complete mutation; `withArchiveMaintenance(dataDir, task)` blocks new writers and waits for existing leases and tracked promises. `createArchiveRequestHandler()` retains admission until the actual handler promise settles even after an HTTP abort, while `trackArchivePromise()` includes detached continuations. The restore manager pauses and drains the outbound worker before reading the selected Drive source, pins the exact local/remote/target evidence before long work, then stages and validates a total allowlisted replacement under a durable journal. Rollback captures raw allowlisted bytes, so a malformed old catalog can still be repaired. Restore completion preserves the selected mode for manual restore, including equivalent and semantically empty valid snapshots; activation enables only after an explicit `use-drive` choice. Build config is passive and does not recover, initialize, sweep, or write archive controls.

Feature 03's `authorizeRestore`, `invalidateAfterRestore`, and `completeRestore` seams carry a durable restore capability bound to the confirmed target/source and transaction. `bindRestoreIncoming()` binds raw previous and verified incoming fingerprints before any replacement intent, and `verifyRestoreJournal()` checks the persisted target, source, mode, transaction, epoch and transform proof at recovery boundaries. The worker stays paused through `completeRestore({ keepPaused: true })` until the durable `committed` journal marker is saved, then `finishRestore({ expectedProof })` applies the prior manual mode or explicit activation. A persisted `lastRestoreProof` permits safe cleanup after a completed restore across restart. Startup validates the journal before recovery, resolves interrupted rename boundaries under maintenance, and does so before every cooperating writer or outbound resume. A CLI without the worker retains a committed journal and blocks writes until backend recovery can complete the source-bound proof. Malformed control records are preserved and surfaced as safe errors.

Prepared CLI/agent outputs record `provenanceGeneration` before external generation begins. Apply compares it with the maximum local metadata/browser generation while holding the archive lease; pre-provenance legacy manifests are accepted only on the original pre-restore generation. Web import jobs carry their admitted generation and stale completion/replay is rejected or quarantined. `archive-generation.mjs` provides a lease-protected capture command for agents. The bundled import and outfit skills document capture-before-work and apply-time fencing.

On browser-state generation change, `App.jsx` clears wardrobe, outfits, inspo/wishlist, cheat sheets, preferences, viewers and derived UI state before reloading server domains; generation checks discard late replies. `archiveImageSource()` routes portable roots and legacy root aliases through the archive asset API with `archiveGeneration` in the URL. `OptimizedImage` uses that versioned source before IPX normalization, so same-path restored bytes cannot reuse an old transform cache entry.

Structural archive validation now checks each supported catalog domain beyond its identity field: nested library variants/references and media descriptors; outfit piece/item-ID arrays; inspo and wishlist arrays/status/media; cheat-sheet pieces, bands/settings, revisions and images; plus existing preferences, browser-state and metadata schemas. Legacy id-only records and historical references to removed records remain accepted. Referenced persistent media paths must be bounded archive-relative allowlisted paths and present in the inventory. Tests use temporary directories and fake Drive/provider implementations only.

Startup migrations use a separate structural preflight before defaults, normalization, or interrupted-job replay. If a local catalog is malformed, startup preserves its bytes and skips those writers while leaving the Drive repair API available. The preflight recognizes bounded external media strings in supported historical records so they can reach the existing migration path; publication and restore continue to use strict `validateArchive` checks for portable, inventoried media.

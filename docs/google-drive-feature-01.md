# Feature 01 — Complete portable local archive

## Scope and ownership

Implement the first feature in `google-drive-implementation.md`: make the current React/Vite/Node local archive complete, portable, and reusable by later Google Drive work. This feature does not add OAuth, Drive transfers, a background queue, restore orchestration, or Drive settings.

The backend and configured `WARDROBE_DATA_DIR` remain authoritative. All tests use temporary repositories/data directories and mocked AI; neither the real archive nor `.env` is a verification fixture. One backend may mutate the archive, with multiple browsers attached. CLI importers continue to coordinate library mutations with the existing file lock.

The CODER owns the archive/storage modules, importer integrations, persistent browser state integration, relevant skill instructions, tests, and focused documentation required below. Existing React components, middleware plugins, schema v2 records, import candidate identities, and public API asset URLs remain compatible.

## Observed gaps

- Web import decodes and normalizes an upload, calls AI, and only then puts normalized PNGs under `data/jobs/`. Rejection/completion removes that directory; the actual uploaded bytes are never retained.
- Bulk import reads external photos, stores source basenames in prepared manifests, and creates processed assets without retaining source bytes in the archive. Applying a manifest may leave references to inaccessible filenames.
- The agent importer stores cutouts/modeled PNGs and arbitrary manifest reference strings. Its skill creates working copies before preserving a durable original in the archive.
- Local browser state includes item edits/deletions, color profile, declutter kept decisions, suggestion nudge dismissals, preferred model tier, onboarding dismissal, and worn-today checkmarks. Suggestions read the browser color profile directly. Session onboarding/provider-switch flags are temporary and are not archive state.
- Asset fields currently store `/api/...` routes on disk. Outfit agents may also use `outfit-images/`. Environment reference paths can point outside `data/` and then escape a simple directory backup.
- `data/jobs/`, derived `identity-profile.json`, `public/drapes/`, migration snapshots, locks, and atomic-write temporary files are processing/cache state. They must not enter the user archive.

## Archive boundary and storage contract

Add a dependency-light shared asset/path module and server archive module. Public API responses keep current asset URLs; catalogs on disk store POSIX relative paths rooted in `WARDROBE_DATA_DIR`, for example `imported/item-garment.png`, `outfits-assets/outfit-modeled.png`, `originals/<digest>.<extension>`. No required Drive IDs or external absolute file paths are introduced.

The inventory is an explicit allowlist, not an unrestricted recursive walk. Persistent catalogs include `library.json`, `outfits.json`, `inspo.json`, `wishlist.json`, `cheat-sheets.json`, `preferences.json` (existing behavior/wear history), `color-profile.json`, browser preference state, archive schema/migration metadata, AI mode, and durable source provenance if stored separately. Persistent media roots include `imported/`, `outfits-assets/`, `outfit-images/` (agent output), `inspo-assets/`, `wishlist-assets/`, `cheat-sheets-assets/`, and `originals/`. Include canonical full-body/face reference files. Include any other discovered current persistent user domain explicitly, with evidence in the final notes.

Exclude `.env`, credential/token/OAuth/sync-control files, unknown files, jobs, drape/identity caches, backup/version snapshots, lock directories, temporary/staging files, node modules, source code, and public static application assets. Symlinks and traversal/absolute paths must not escape the boundary; reject them clearly instead of reading unintended files. File reads, corruption, and permission errors must not be converted into an apparently empty successful inventory.

Expose deterministic inventory and validation primitives to later owners. Each file entry contains `{ path, size, sha256 }`, entries are sorted by portable path, and the envelope carries an archive schema version. Hash the actual bytes. Validation checks schema, duplicate/unsafe paths, size/checksum mismatches, and missing referenced local media. Missing legacy originals are reported as a historical limitation, not invented or silently rewritten as available files. Unknown unreferenced files and excluded control state do not become backup members.

Provide a preparation/migration function for existing catalogs and configured references. Run it during backend configuration and real CLI import entrypoints, without requiring a Drive connection. A copy of external model/face references must live in the canonical archive directory; runtime resolvers use the archived fallback on a copied installation where the previous external path is absent. Setup changes update the canonical archive copy. Preserve existing reference-setting compatibility without writing configuration secrets into the archive.

Asset conversion must work at real read/write boundaries, not merely in unused utilities. Existing writers (including library locking and common atomic JSON helpers) persist relative fields; readers/HTTP response boundaries provide the compatible URLs expected by current components. Preserve non-local source URLs and descriptive labels. Handle nested variants, references, thumbnails, modeled photos, outfit images, and cache-busting query strings consistently. Reject local media paths with traversal. CLI media resolution continues to work after conversion.

## Original preservation and provenance

Provide one shared `preserveOriginal` primitive for unchanged byte buffers/files with stable archive-relative identifiers, correct MIME/extension metadata, and a checksum. Content-addressed files may reuse identical source bytes; this never deduplicates garment occurrences or changes independent `importId` values. Original media remain persistent even when a job fails, detects no items, is rejected, completes, or is cleaned up. Do not couple original deletion to temporary job cleanup.

Web import saves the raw upload before image normalization or any AI call. The resulting stable original path is copied into job provenance and accepted item's references. Preserve normalized/crop images separately only if needed by accepted reference semantics. Add an archive asset route for durable originals, bounded to safe allowed paths. Photo-based variant/reference additions, inspiration/wishlist ingestion, and setup reference uploads also preserve incoming originals before AI/normalization where they represent new user source photos. Existing cropped/processed views keep their public behavior.

Bulk import saves each source before normalization/detection. Real imports preserve originals in the configured archive. `--prepare` retains byte-exact originals beside the manifest before AI, so reviewed output can be applied after the input folder disappears; apply copies those sources into the archive and rewrites actual asset references. `--dry-run` must not mutate the wardrobe: preserve pre-AI originals in an isolated temporary workspace if AI is still executed. Use paths/metadata in generated candidates so direct and prepared flows retain provenance for every accepted independent occurrence. Reject unavailable declared source references on new manifests; allow explicit compatibility for old manifests without recoverable originals and report that limitation.

Agent workflow adds a deterministic pre-generation source capture command. The skill invokes it before creating converted copies, cropping, or calling Imagegen. Manifests point to captured originals; the final importer reuses the shared preservation/import helpers and honors `WARDROBE_DATA_DIR`. The skill's outfit delivery instructions use archive-relative paths, and its source resolution supports both current API URLs and relative catalogs. `.agents` is protected: if edits require escalation, request `require_escalated` for the authorized exact edit; do not bypass protection via symlinks/copies or omit this integration.

## Browser persistence and migration

Add backend browser preference storage plus a small client module/hook using the existing fetch helper. Backend storage is atomic, serialized, schema validated, and supports field-level updates or set-membership operations to avoid unrelated browsers overwriting each other. Defaults are supplied for missing files only; invalid stored JSON is an error, not a reset.

Consolidate the following domains and integrate every current consumer:

| Browser domain | Canonical behavior |
| --- | --- |
| Item edits | Existing library PATCH is authoritative; import legacy browser edits once into persisted records or a deliberate backend overlay, then remove normal browser overlays. |
| Item deletions | Backend mutation/tombstone supports all IDs; browser-only deletion cannot remain the record. |
| Color profile | Existing backend color-profile store is authoritative; migrate a legacy profile only if needed; App, modal, and suggestions use backend/current shared state. |
| Declutter kept IDs | Backend set persists user decisions. |
| Dismissed nudges | Backend set persists dismissals. |
| Remembered model tier | Backend scalar preference shared by generating panels. |
| Onboarding dismissed | Backend scalar preference; resume/provider-switch session flags stay temporary. |
| Worn-today checkmarks | Existing wear signal history remains authoritative; derive checkmarks or store day/outfit IDs on backend, migrate today's legacy checkmarks without inventing wear history. |

On initial connection submit validated legacy values only once; do not erase browser values until the backend acknowledges persistence. A persisted archive marker/version records migration completion and backend values subsequently win. Multiple browser requests must not lose unrelated updates. A cold mount/refocus must load server state before decisions depend on migrated data. Do not keep writing authoritative values to localStorage or mask failed backend mutations as successful saves. The local color profile may be an in-memory rendering cache, never a required data source.

Expose a `sealLegacyBrowserMigration`/equivalent handshake for feature 04: restoring or initializing an archive can disable all future legacy seeds and invalidate client caches with an archive generation change. This avoids a browser reimporting old edits/deletions after restore. Initial migration is first successful authoritative import; stale values from another browser must not overwrite fields already present. Document any unavoidable historical ambiguity in old caches lacking timestamps.

## Implementation evidence and handoff

### Implemented contracts

- `scripts/archive-store.mjs` exports `ARCHIVE_SCHEMA_VERSION` (1), `ARCHIVE_CATALOGS`, `ARCHIVE_MEDIA_ROOTS`, `buildArchiveInventory(dataDir)`, `validateArchive(dataDir, inventory)`, and `resolveArchiveFile(dataDir, relativePath)`. The inventory envelope is `{ version: 1, files: [{ path, size, sha256 }] }`. Validation returns `{ valid, errors, historicalMissing }`; enumeration failures propagate. Sync and restore must use the same allowlist and bounded resolver, rather than recursively copying the whole data directory.
- `preserveOriginal({ dataDir, bytes, filePath, mime, filename })` returns a byte-exact content-addressed descriptor with `path`, `size`, `sha256`, `mime`, `extension`, and original basename. `prepareArchiveDirectory` archives configured external reference bytes and creates normalized canonical PNG references. `readReferenceBytes` also finds canonical references after the external source disappears and recognizes their actual image bytes/MIME. `migrateCatalogAssetPaths` converts existing catalogs without rewriting unrelated IDs or labels.
- `shared/portable-assets.mjs` supplies `safeArchivePath`, `archivePathFromAsset`, `diskAssetPath`, `publicAssetUrl`, `catalogForDisk`, and `catalogForHttp`. Disk catalogs contain archive-relative media paths; HTTP responses retain compatible public asset routes. Originals and agent outfit images can be served by `/api/archive/assets/<relative-path>`.
- `scripts/capture-import-sources.mjs` supplies the pre-AI agent capture CLI and `captureImportSources`. The manifest records recursive source-relative names so identical basenames in different folders remain distinguishable. The final agent importer verifies/copies these descriptors into the configured archive; generated garment occurrence IDs remain independent.
- `scripts/browser-state-api.mjs` supplies `readBrowserState`, `markBrowserStateFields`, and `sealLegacyBrowserMigration`. HTTP endpoints are GET `/api/browser-state`, POST `/api/browser-state/migrate`, POST `/api/browser-state/update`, and POST `/api/browser-state/seal-legacy-migration`. Updates serialize per archive and support atomic set membership, including dated `wornToday` membership. The client adapter in `src/browser-state.js` collects only present, valid legacy keys and removes only acknowledged values. An empty new browser cannot close migration for absent fields; authoritative backend edits mark their domains before a late legacy browser can overwrite them.
- `src/browser-state.js` also exports `createBrowserStateClient`, `useBrowserState`, `ensureBrowserStateReady`, and `refreshBrowserState`. Consumers share a loading/error/state snapshot, refresh on window focus or document visibility, and invalidate archive-derived state on generation changes. Incoming responses are accepted monotonically by `(archiveGeneration, revision)`; older responses or errors cannot roll back the current snapshot or request status. Normalized no-op migrations/updates leave revision and file bytes unchanged. Preference-dependent controls wait for readiness before writing.
- `scripts/preferences-api.mjs` exports `recordSignalStrict(dataDir, input, idempotencyKey)` for a user-visible durable transaction. Worn membership writes history first with `worn:<day>:<outfitId>`, then the checkmark; retry after either write fails completes the operation without a duplicate event. Corrupt history remains untouched and fails the strict operation. Existing secondary telemetry-style preference signals keep their previous best-effort behavior.

### Boundary and historical limits

The persistent catalogs and media roots are the explicit exported allowlists above, including AI mode, browser preference state, color profile, preferences/history, full-body and face reference photos, and original source bytes. Derived `style-dna.json`, `identity-profile.json`, public drape images, jobs, locks, atomic-write temporary files, snapshots, credentials, `.env`, and future OAuth/sync control state are excluded. Hidden/control names within media roots are excluded consistently from inventory and bounded resolution. Non-local source URLs remain URLs and are not downloaded into an archive by the codec.

Originals removed before this feature cannot be reconstructed. Old manifests without captured source descriptors retain explicit legacy compatibility; new capture manifests require their declared sources to exist and match their checksums. An original source file may be shared by byte hash, while each detected garment occurrence remains a separate record. Originals currently accumulate independently of job cleanup; no garbage collection policy is introduced in this feature.

Legacy browser caches do not have trustworthy timestamps. The first acknowledged value for a domain wins unless the backend already owns it; failed migration keeps usable legacy browser data. The backend migration seal is the restore handshake: feature 04 must make the restored generation greater than both the previously active local generation and the remote generation, call `sealLegacyBrowserMigration`, then reload/rebootstrap mounted clients using the new `archiveGeneration`. A simple increment of an older restored generation can collide with a previously observed value, so the restore coordinator must carry the pre-restore generation across replacement. The client refreshes shared state on focus/visibility and uses generation changes to invalidate archive-derived state. This feature provides the marker and adapter; it does not implement restore, a global mutation gate, or live cross-browser event broadcasting.

### Handoff to features 02–05

- Feature 02 can use the local archive schema and preparation contracts without storing credentials in archive catalogs or media. Keep OAuth credentials and connection/folder control state outside the exported boundary.
- Feature 03 can build/verify a complete latest-copy manifest from `buildArchiveInventory` and `validateArchive`, and resolve only its approved members through `resolveArchiveFile`. Preserve raw original descriptors and independent garment IDs. The current inventory is an enumeration primitive; later code must coordinate writes to obtain a coherent snapshot and implement queue/retry/status behavior.
- Feature 04 must stage and verify the complete archive before atomic replacement, preserve rollback data, seal legacy browser migration, and invalidate mounted client caches. Waiting for HTTP requests alone is insufficient: import jobs have `running` and `runningModeled` promises; variants have `running` and `runningPipelines`; outfits have `running`; inspiration detection has `detecting`; wishlist retries have `retrying`; cheat sheets have `running` plus `mutationQueue`. These maps are currently private to their plugins. Expose/register their live promises with a restore coordinator and block new mutation admission before draining them. Bulk import/apply, outfit regeneration, source capture, and agent import are non-HTTP writers that must join the same ownership/maintenance protocol. Existing library locking and atomic JSON writes protect individual writes, not an entire restored archive.
- Feature 05 can compose the connection/sync/restore services and show backup status in settings. Reuse the backend browser-state adapter for persistent preferences and handle archive-generation refresh after restore; do not reintroduce browser-only edits, deletions, or color profiles.

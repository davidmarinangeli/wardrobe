## Actual safe API contracts

Use a dedicated client request helper for structured `{ error: { code, message, retryable } }` errors; the generic API helper currently assumes string errors. Display curated/localized messages and safe fields only. Keep internal account/folder IDs, fingerprints, connection generations, action/operation tokens and sessions out of rendered content, logs, titles and attributes. The opaque token may exist only in client control state and POST payload.

| API | Client behavior |
| --- | --- |
| GET `/api/google-drive/status` | Read mode from `backupEnabled`, auth `state`/`connected`/`reconnectRequired`, account email/name, folder name/read/write capabilities, sync counts/errors/paused/pending/last completion, maintenance and restore. Never treat read failure as disconnected, local-only, or empty. |
| POST `/api/google-drive/oauth/start` `{}` | Explicit connect/reconnect; navigate only to a validated Google authorization URL. Does not enable backup. |
| POST `/api/google-drive/verify` `{}` | Explicit account/folder verification; refresh merged status afterward because response is auth-only. |
| POST `/api/google-drive/disconnect` `{}` | Explicit local disconnect; leave archives untouched. Disable/drain backup first when selected and confirm the operation's effect. Refresh merged status afterward. |
| POST `/api/google-drive/archive/activation/preview` `{}` | Read opaque `actionToken`, operation, decision, allowed choices, validity/populated flags and file/byte counts. The worker is paused while this preview awaits a choice. |
| POST `/api/google-drive/archive/activation/choice` `{ actionToken, choice }` | Submit only a choice advertised by the current preview; `cancel` must reach the server, not just dismiss local UI. `use-drive` starts a long operation; other authorized choices complete immediately. |
| POST `/api/google-drive/archive/restore/preview` `{}` | Manual restore preview. Only a valid complete Drive archive permits `use-drive`, plus `cancel`; invalid/unavailable stays an explicit error. |
| POST `/api/google-drive/archive/restore/confirm` `{ actionToken, choice: "use-drive" | "cancel" }` | TOTAL replacement after explicit confirmation. Server preserves the prior storage mode. Running response contains opaque `operationId`. |
| POST `/api/google-drive/archive/disable` `{}` | Drain/disable and keep both local and Drive copies. Do not delete any copy or disconnect implicitly. |

Preview decisions are `local_to_empty`, `drive_to_empty`, `initialize`, `equivalent`, `different`, `local_invalid`, and `unavailable`. Valid choices are `use-local`, `use-drive`, `initialize`, `equivalent`, `cancel`, constrained by the response. Tokens expire after ten minutes; stale evidence/changed bytes/target is rejection, requiring a new preview and fresh consent. No blind enable route or client-side alternative selection.

Restore status has `{ operationId, stage, progress, startedAt, error }`. Stages currently include running, capturing, fencing, replacing, sync_commit, complete, failed and recovery_required. Maintenance may be active while waiting for admitted background work before a progress transition. Show an indeterminate waiting state when work is draining and a progress bar for the server's numeric progress. Never announce success on a merely accepted HTTP response or while maintenance remains active. A recovery-required error must not re-enable mutation affordances prematurely.

## Client lifecycle and stale-response contract

Implement a small dependency-light controller/store that is importable by Node tests, with the React hook/view as thin consumers. Poll status passively while App is mounted (bounded intervals, no overlaps), accelerate during restore, and refresh on focus/visibility. Status failure preserves the last acknowledged snapshot and displays an error; it cannot make a populated/connected archive appear empty or disabled.

Every operation binds to a lifecycle/action sequence and current target identity in control state. Beginning connect/reconnect/disconnect/disable/preview/choice invalidates prior poll/action completions. Responses arriving after a newer request, changed target, cancellation, unmount or generation must not resurrect previews, connection, selected mode, errors, or progress. A stale preview that the server created must be explicitly canceled when it is still safe/owned; do not drop it while leaving its worker paused. During actions, prevent overlapping polls from publishing incomplete auth-only/control responses. After auth-only actions reread merged status. Discard private fields when shaping presentation; render no raw API JSON.

Use timers with cleanup and serialized operations rather than optimistic toggle writes. Backoff on failed status reads; do not poll live Google from the browser. An operation response is acknowledgment, not authorization to apply stale UI state. Rejected evidence clears confirmation and asks the user to inspect a fresh preview. Cancellation failures stay visible and retryable; do not silently assume resumed synchronization.

- [Consent configuration](https://developers.google.com/workspace/guides/configure-oauth-consent): personal account uses External audience/test users while testing; organization-only Internal is not the ordinary personal-account route.
- [Refresh expiration](https://developers.google.com/identity/protocols/oauth2#expiration): External + Testing refresh tokens expire after seven days for Drive scopes; reconnect is expected. Tokens can expire/revoke for other reasons too. Do not claim everlasting access or promise verification approval; distinguish personal testing from public publication.
